# NLP и обработка текста

NLP - Natural Language Processing

NLP - то, что было до LLM

Схема: Исходный текст -> Подготовка -> Вектор (Embedding) -> Результат

NLP решает следующие задачи:
поиск документов; 
определение темы; 
анализ тональности; 
извлечение имён, организаций и дат; 
поиск ключевых слов; 
перевод; 
ответы на вопросы.

Эмбеддинг - вектор 32 чисел float32 - 128 байт.
Зачем здесь PostgreSQL? - храним векторы в БД и ищем их для сравнения, а вычисление в Python


Текст != числа. Нейросети и большинство ML-алгоритмов работают с числовыми Tensor или матрицами. Поэтому между исходной строкой и моделью необходим этап представления текста.

Текст -> Токены -> Числа -> Модель

Просто переводить буквы в числа - неэффективно. Плохо работает LLM построена на предсказании букв.

Перешли к токенизации - разбиение текста на единицы обработки. Но возник вопрос, где границы слова. 

Также важна нормализация (приведение к общего регистру например), но нормализация может быть и вредна (если убрать знаки препинания например).

Можно убирать стоп-слова, но тоже осторожно. Стоп-слово может нести смысл, а его удалили - плохо.

Также есть стемминг - отсечение окончаний, и лемматизация - приведение слова в  нормальную форму (без приставок и т.д.)

В обще текст, еще обрабатывают перед отправкой в модель.

В питоне для этого есть библиотека промышленной обработки текста: spaCy

spaCy помимо обработки текста как сказано выше еще и выделяет сущности в тексте

Еще есть инструмент NLTK - Natural Language Tool Kit, тоже есть какие-то инструменты обработки.

Есть BoW - Bag of Words. Таблица сколько слов повторяется в тексте.

Есть TF-IDF (Term Frequency, Inverse Document Frequency) которые уменьшают вес часто встречаемых слов (тех же предлогов)б потому что они мало несут смысла.

Итого: BoW -> Частые слова -> TF-IDF

Есть Word2Vec - каждому слову ставит вектор. Вместо вектора целому окну.
Есть Continous BoW и Skip-gram, fast-text 

Это целые модели для обработки текстов.

Каждому слову по матрице эмбеддингов сопоставляется вектор. Матрица делается моделями как Word2vec и тд.

Если идем к обработке и работе с предложениями, то работаем с Sentence Transformers (BERT, GPT)

Итого есть 4 подхода:
BoW — частоты слов.
TF-IDF — статистические веса слов.
Word2Vec / FastText — обучаемые векторы слов.
LSTM / Sentence Transformers — векторы последовательностей (но цели обучения разные).


Но есть и вообще задача классификации текста, там эмбеддинги вообще не нужны:
Задача: текст → класс (например, отзыв положительный/отрицательный).
Пайплайн: тексты → TF-IDF → LogisticRegression → вероятность класса.

При определении тональности важна правильная обработка стоп-слов.
Для поиска ключевых слов часто используется TF-IDF
Для поиска сущностей используется spaCy (NER - Named Entity Recognition)


Типичные ошибки при подготовке текста:
Случайное перемешивание временных документов; 
дубли между TRAIN и TEST; 
разный preprocessing при обучении и inference; 
неверная кодировка; 
OCR-ошибки.

---

Итого:
Токенизация — как делим текст.
Нормализация — какие различия устраняем.
BoW / TF-IDF — статистические представления.
Word2Vec / FastText — векторы слов.
LSTM / Sentence Transformers — представления контекстов и предложений.

Главный принцип: выбираем представления под задачу, а не наоборот

Как этот пайплайн (Python + PostgreSQL) выглядит в жизни Но это еще не LLM, это скорее про классификацию текстов:

1. **Этап подготовки (Офлайн):** Вы берете 1 000 000 статей → Прогоняете через Python-модель → Получаете 1 000 000 векторов → Сохраняете их в Векторную БД и **строите индекс**.
2. **Этап запроса (Онлайн):**
    - Пользователь пишет: _«хочу почитать про котиков»_.
    - **Python:** мгновенно превращает эту фразу в один вектор `[0.12, -0.43, ...]`.
    - **БД:** Python отправляет этот вектор в базу данных. База по своему **индексу** за 5 миллисекунд находит ТОП-5 самых похожих векторов статей.
    - **Результат:** БД возвращает в Python ID этих пяти статей, и вы показываете их пользователю.
