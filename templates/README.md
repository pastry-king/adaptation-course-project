# Шаблоны результатов

- `experiments.csv` — **только заголовок** журнала. При реализации создать `experiments/experiments.csv` с этим заголовком и дописывать через `csv.DictWriter` по одной строке на запуск; не менять порядок и имена колонок. Даты — ISO 8601; десятичный разделитель — точка; текстовый файл — UTF-8. `validation_*` и `forecast_*` — результаты одного и того же запуска, не разных моделей. При `failed` незаполненные метрики остаются пустыми, причина пишется в `error_message`.
- `report.html.j2` — шаблон [Jinja2](https://jinja.palletsprojects.com/). Рендерить с `Environment(autoescape=True, undefined=StrictUndefined)`, передавать `report` (словарь со значениями эксперимента) и `plots` (объекты `title`, `alt`, `caption`, `file`, `data_file`, `data_uri`). PNG встроен как `data_uri`, поэтому HTML можно читать отдельно; ссылки на PNG и числовой CSV доступны рядом с отчётом.
- Структура `report`: общие поля `schema_version`, `experiment_id`, `created_at`, `status`, `hypothesis`, `changed_factor`, `factor_level`, `controlled_conditions`, `conclusion`, `limitations`; словари `dataset`, `splits`, `configuration`, `training`, `software`, `artifacts` с названиями полей, указанными прямо в шаблоне. `metrics` содержит две группы — `validation` и `forecast`; в каждой — `lstm`, `last_hour`, `yesterday`, `last_week`, и у каждого прогнозиста численные `mae`, `mse`, `r2`.
- В готовом HTML есть машиночитаемый JSON (`<script id="experiment-data" type="application/json">`) со всем `report`, а таблицы содержат `data-stage`, `data-model`, `data-metric` и точные `data-value`. Числа в тексте округлены лишь для чтения; из JSON/`data-value` можно получить исходную точность. Для безопасного JSON внутри HTML используется фильтр Jinja2 `tojson`.
- В `experiments/graphs/<experiment_id>/data/` лежат **полные данные**, а не только видимые фрагменты: `timeline.csv` (весь почасовой ряд), `training_loss.csv` (каждая эпоха), `validation_predictions.csv` и `forecast_predictions.csv` (каждый час: факт, LSTM, три наивных прогноза и ошибки `факт − прогноз`, кВт·ч). Время записано как местное время источника без UTC-смещения. На графике ряда показан каждый 12-й час, на графиках прогноза и ошибок — последние 168 часов; полные CSV позволяют исследовать и остальные точки.
- `experiments/graphs/<experiment_id>/manifest.json` сопоставляет каждый PNG с CSV, отображаемыми столбцами и выбором строк, фиксирует единицы, ID эксперимента, путь к HTML и SHA-256. Те же ссылки находятся в машиночитаемом JSON отчёта. Структура общего CSV-журнала не менялась: связь по колонке `experiment_id`.

`schema_version = 1`; изменения схемы после появления реальных отчётов требуют новой версии. Не записывать в JSON `NaN`/`Infinity`: при некорректной метрике сообщить об ошибке запуска, а не создавать невалидные результаты.
