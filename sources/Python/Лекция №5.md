# Дебаггинг, откладка кода

Путь диагностики: 
print - IDE - pdb - logging - TensorBoard

Классы ошибок ML:
SyntaxError - программа упала
Labels wrong - программа работает
Leakage - метрики обманывают

Нужно различать ошибки кода, данных, обучения и методики обучения

Самый быстрый способ увидеть состояние программы - print():
- проверка размерности shape
- проверка диапазонов и NaN
- проверка loss (снижение, плато)
- проверка градиента, забыли ли оптимизатор optimizer.step()
- проверка изменения весов

Затем есть средства IDE:
- сам дебаггер - проверяем в момент выполнения
- можно наблюдать вызовы, переходы в методы
- можно сразу смотреть вычисляемые выражения
- можно понять кто вызвал функцию

Еще есть pdb в терминале:
- дебаггер вне IDE
- есть набор типовых команд: step, next, continue
- можно смотреть реальные данные в Tensor во время паузы

Перепутанные метки, обучение на неверных данных (X -> Y)
Слишком большой learning rate, обучение не стабильно
Всю генеральную выборку делим 30/70 обучение/тест
Журналы (logging) - дополнение к print
Структурированное журналирование (машиночитаемые поля)
TensorBoard - показывает кривые обучения и распределение параметров
Проверка градиентов и весов по эпохам - смотрим изменения модели, а не только loss
Мониторинг ресурсов (CPU, RAM, GPU) - смотрим дороговизну по ресурсам
Есть какой-то механизм Checkpoint - ?
Отчет должен содержать: симптомы, шаги воспроизведения, измерения, причину, исправления - другой инженер сможет воспроизвести
