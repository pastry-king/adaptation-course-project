Реляционные БД - PostgreSQL

Большие бинарные объекты могут жить отдельно, но характеристики объектов должны быть запросимы
PostgreSQL - про управление метаданным (фильтрация, соединения, контроль качества, воспроизводимость)

Теория:
Отношение - таблица, у нее есть схема - т.е. набор атрибутов
Кортеж - одна запись отношения
Атрибут - именованный признак, у него есть домен допустимых значений

Первичный ключ - идентификатор строки в модели

DDL - Data Definition Language - как описать хранимые данные
DML - Data Manipulation Language - как управлять данными (некий CRUD)

NULL = "значение отсутствует/неизвестно", NOT NULL - значение обязательно по смыслу

Первый DDL - схема, имеет название и атрибуты, в атрибутах указывается первичный ключ, допустимые значения, проверки значения, значения по умолчанию

Кто проверяет валидность введенных данных? - Оба! И БД и само приложение! СУБД должно отвергать некорректные изменения/состояния

UNIQUE атрибуты - есть атрибуты, строки должны иметь различаемые значения

Нормализация - убираем избыточность, нормальные формы

Связь M:M - делается через промежуточную таблицу, которая делает два связи 1:M

Часто для быстрой обработки делают ДЕНОРМАЛИЗАЦИЮ

VIEW - интерфейс поверх самой таблицы

JSONB - эффективной поиск

PostgreSQL - выполняет еще и поисковую функцию (FTS)

Выбор СУБД определяется требованиями системы, а не форматами файлов

В СУБД необходимо выполнять принцип минимальных привилегий - уменьшает цену ошибки

Транзакционность (ACID) - изменения (несколько) либо принимаются полностью, либо отменяются

В контексте AI/ML используется для подготовки выборки обучающих данных. При этом PostgreSQL не должен хранить все подряд.

Большие файлы не хранятся в БД, в ней хранятся ссылки на blob'ы
