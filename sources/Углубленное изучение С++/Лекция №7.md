# Оптимизация

Ускорение необходимо доказать ускорение.
Фиксируем объем входа, метрику и корректность.
Замеряем исходную версию, меняем один фактор, повторяем
Результат зависит от CPU, компилятора и окружения

Важно как раз таки понимать copy/move semantics. Когда копируется массив или на ссылаются на старый.

Также важно учитывать выделение памяти. Можно резервировать, можно динамически выделять (?)

Также важно учитывать локальность кэша в процессорах. Буквально то, что будет загружаться в процессор.

Для начала делаем некий benchmark:
для этого прогреваем CPU - делаем много запусков - медиану берем как итоговое значение

Есть разные уровни оптимизации кода (-O0 и -O2). С помощью них можно сравнить время выполнения.
Есть timer и profiler, они показывают время и место каких-то частей кода.
Также есть механизмы (-Wall, -Wextra, - Wpedantic) которые выявляют подозрительный код.
Помимо этого, еще есть некий Address Sanitizer, который ищет другие ошибки доступа к памяти.
Есть еще Leak Sanitizer, который ищет ошибки утечки памяти. Но лучше полагаться на RAII и STL.
Еще есть Undefined Behavior Sanitizer
Есть Thread Sanitizer.
Все sanitizer не взаимозаменяемые. Для каждого инструмента нужна своя сборка.
Также есть clang-tidy и cppcheck.

Code review:
- проверяем не только стиль, но и контракты
- тесты нужна для определения корректности работы
- измерения делаем через perf

---

Итого:

Ускорение - это проверенная гипотеза. Есть baseline - старый вариант, делаем изменение, замеряем снова.
