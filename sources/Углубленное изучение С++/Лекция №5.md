# C++ шаблоны, STL и ranges — простыми словами

## Самое главное
Не обобщай код ради обобщения. Сначала реши конкретную задачу. Если видишь, что один и тот же код нужен для разных типов, — тогда используй шаблоны. Готовые инструменты (STL) и удобные цепочки (ranges) помогают, но не заменяют понимание и измерения.

---

## 1. Шаблоны
- **Шаблон** — это как форма для выпечки: одна форма, а начинка может быть разной.
- Пример: функция `square(T value)` работает и для `int`, и для `double`.
- Если тип только один, шаблон чаще всего не нужен.
- `class` и `typename` в шаблоне — почти одно и то же.
- Если компилятор не может сам понять тип, укажи его явно:  
  `maximum<double>(2, 5.5)`.

## 2. Ограничения типов (concepts)
- Шаблон может принимать не любой тип, а только подходящий.
- **Concept** — это правило: например, «тип должен быть числом».
- `requires` проверяет, что для типа можно сделать нужную операцию (например, умножить).
- Важно: concept проверяет синтаксис, а не смысл.  
  Например, он не проверит, что уверенность лежит от 0 до 1 — это проверка во время выполнения.

## 3. STL — готовые инструменты. Три составляющих
- **STL** — это набор готовых контейнеров и алгоритмов.
- **Контейнер** — где хранятся данные:
  - `vector` — динамический массив (основной выбор для ML-результатов);
  - `array` — фиксированный размер;
  - `map` — упорядоченный словарь;
  - `unordered_map` — хеш-таблица.
- **Алгоритмы**:
  - `sort` — сортировка;
  - `remove_if` — удаление по условию;
  - `accumulate` — суммирование.
- **Итераторы** — способ пройти по контейнеру.  
  `begin()` — начало, `end()` — конец (не указывает на элемент).

## 4. Ranges — цепочки операций
- Ranges позволяют соединять операции в удобный конвейер.
- Пример: отфильтровать → преобразовать → вывести.
- **Views** ленивые: элементы не копируются, пока не понадобятся.
- Но нужно следить, чтобы данные, на которые ссылаются views, жили достаточно долго.
- Ranges не ускоряют код автоматически и не заменяют правильный выбор структуры данных.

## 6. Сравнение подходов
- **A:** обычный цикл + `sort`.
- **B:** `remove_if` + `sort` + `accumulate`.
- **C:** ranges: `copy_if` + `sort` + `accumulate`.

Что важно при замерах:
- Сначала проверить, что результаты одинаковые.
- Замерять в Release (`-O3 -std=c++20`).
- Прогревать, повторять, брать медиану.
- Не включать в замер генерацию данных.
- Фиксировать размер входа, порог, компилятор.

Типичные ошибки:
- одна версия копирует данные, другая меняет исходные;
- одна выделяет память, другая нет;
- результат не используется, и компилятор выкидывает вычисления;
- вывод в консоль попадает в замер.

## 7. Итоги
1. Шаблон нужен только тогда, когда без него реально плохо.
2. Concepts задают правила, но не гарантируют смысл.
3. STL даёт готовые и проверенные инструменты.
4. Ranges удобны для цепочек, но требуют внимания к времени жизни данных.
5. Решай по корректности и измерениям, а не по моде.

## Мини-словарь
- **Шаблон** — обобщённый код для разных типов.
- **Concept** — правило, какой тип подходит.
- **STL** — стандартная библиотека шаблонов C++.
- **Контейнер** — хранилище данных.
- **Итератор** — указатель на позицию в контейнере.
- **Ranges** — удобные цепочки операций над диапазонами.
- **View** — ленивое представление данных.
